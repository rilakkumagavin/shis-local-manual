第一次安裝？開啟完整安裝圖解教學

開發者：桃園市青溪國小 黃志豪

01

首次使用

正式系統初始化

  1. 填寫學校資料輸入學校名稱、學校代碼與初始學期。
  2. 建立兩種帳號設定管理員與護理師帳號，兩次輸入密碼確認。
  3. 確認初始化預覽核對學校、學期與帳號資料後再執行。
  4. 完成首次備份初始化完成後確認系統已建立第一份備份。
密碼安全首次登入若系統要求變更密碼，完成後會回到工作台。請勿共用管理員帳號。
02

日常作業

護理師建議操作順序

1確認學期查看頂端目前學期
2找到學生輸入班級座號或學號
3完成登錄勾選部位、分類與處置
4追蹤處理補印通知或查看今日紀錄

緊急處理

直接開啟「傷病登錄」，輸入五碼班級座號，例如 30104。

查詢既有紀錄

開啟「傷病紀錄查詢」，可依日期、班級、學生或待追蹤篩選；工作台的「連續受傷警示」可直接點選學生，開啟該生個人傷病紀錄。

管理追蹤工作

從工作台查看今日傷病、連續受傷、通知與待追蹤項目。

03

學生與學籍

學生查詢與學期編班

先選年級，再選班級與座號；也可以直接輸入姓名或學號。點選學生後，詳細資料會移到畫面可見位置，避免拉到頁面最下方。

學期名冊

  • 每學期重新匯入完整名冊。
  • 身分證或居留證號作為學生主檔識別。
  • 學號、班級與座號可隨學期更新。

轉出與畢業

  • 新名冊未出現者先交由護理人員確認。
  • 轉出或畢業採封存，不刪除健康歷史。
  • 學生轉回時可重新啟用並加入新班級。
04

健康中心核心流程

傷病登錄與歷史修訂

  1. 選擇學生使用班級座號、姓名或學號搜尋；確認同頁的家庭聯絡與健康提醒。
  2. 事件資訊填寫發生時間與地點；觀察時間、生命徵象皆為選填。
  3. 勾選分類依序選擇受傷部位、外傷或內科症狀，可同時勾選多項。
  4. 記錄處置至少選擇一項處置；用藥、送醫或其他處置需補充說明。
  5. 完成或列印可完成紀錄後回工作台，或直接完成並輸出通知單。
修改紀錄在「傷病紀錄查詢」選擇一筆紀錄並按修訂，系統會回到原傷病登錄頁帶入原資料。健康資料不直接刪除，只能修訂或作廢。
傳染病通報與列印在「傳染病通報」完成手動登錄、Excel 匯入或 Google 試算表同步後，於紀錄右側按列印圖示。可切換青溪國小版、光明國小版及衛生局版；輸入本人密碼後才會顯示身分證、地址及家長電話。確認預覽內容後按「列印／另存 PDF」。每次建立預覽都會留下稽核紀錄。
列印前確認空白底線代表來源資料未提供，請先補齊或於紙本填寫；衛生局案件編號、通報人、調查及結案欄位保留給承辦人填寫。含個人資料的 PDF 不可放在公開共用資料夾。
04A

傳染病通報教學

直接產生表單範例

以青溪國小表單欄位為基礎，執行範例程式即可在自己的 Google 帳號建立一份空白通報表及回覆試算表，不含任何真實學生資料。手冊可離線閱讀，建立 Google 表單則需要連線及學校核准的帳號。

下載表單產生程式（.gs） · 開啟 Google Apps Script（新視窗）

  1. 建立專案登入學校核准的 Google 帳號，在 Apps Script 建立新專案。用文字編輯器開啟下載的 .gs 檔，將全部內容貼入專案的「程式碼.gs」，取代原本的空白函式。
  2. 設定校名與欄位將程式開頭 SCHOOL_NAME 改成自己的校名。預設不收集身分證、生日、地址及手機；經校方確認必要性與告知內容後，才將 INCLUDE_SENSITIVE_FIELDS 改為 true。其餘欄位依範例建立；疾病末項已將「選項 8」改為「其他」。
  3. 執行並授權儲存，選擇 createDiseaseReportForm 後按「執行」。首次須審閱 Forms、Sheets 所需權限並授權；若學校政策封鎖，請管理員協助，不要繞過限制。每執行一次都會新增一份表單與試算表，請勿連續重複執行。
  4. 取得三個網址在「執行記錄」取得表單編輯網址、填答網址與回覆試算表網址。編輯網址僅供承辦人使用。表單預設未發布；先核對欄位、個資告知及填答者權限，再於 Google 表單發布並分享填答網址給家長。
  5. 測試匯入先在測試環境以虛構學生填答；姓名填學生本人，班級例如 4-1，座號填數字。從回覆試算表下載 Microsoft Excel（.xlsx），在系統「傳染病通報」匯入，核對姓名、班級、座號、疾病與日期。不要任意更名範例題目，以免無法辨識欄位；不是每個表單欄位都會自動帶入系統。
  6. 其他學校使用分享本手冊與空白產生程式，讓各校自行建立表單。不要分享含真實回覆的試算表或將原始表單編輯權限開放給不相關人員。
回覆資料不可公開目前系統的 Google 同步以無登入方式下載試算表，不能直接讀取限制存取的回覆表。不要為了同步而把含學生健康或個資的回覆表設為公開或「知道連結即可檢視」；請保留限制存取，改由授權承辦人下載 Excel 匯入。自動同步須待校方核准安全存取方式後再使用。
範例與原表單的差異保留基本資料、八類疾病、症狀、就醫、採檢、請假、安親班、兄弟姊妹及疫苗欄位；新增學生姓名提醒，敏感欄位改為可選設定。不沿用原表單的固定停課天數，返校與防疫說明請由校方依適用規定核定。

技術參考：Google Apps Script 表單與回覆目的地官方文件（新視窗）。

資料類型可用功能注意事項
個人疾病史查詢、新增、修訂、匯入、匯出照護指示與病況說明屬敏感資料

06

決策與追蹤

通知與報表

傷病報表

  • 日、週、月與學期範圍。
  • 月份、地點、年級、類型與處置分析。
  • 連續受傷學生與高風險地點警示。

健康分析

  • 視力異常與複檢完成率。
  • 身高、體重與 BMI 分布。
  • 未檢、缺漏、重複與異常值檢核。
匯出前先預覽通知單、Excel 與 PDF 輸出前先確認學期與範圍；敏感匯出需重新驗證本人密碼。
停止使用或更換系統時完整匯出開啟「傷病報表 → 資料匯出」，選擇學年度後可下載教育局既有傷病格式，或包含身分證、學號、完整班級、生命徵象、處置、追蹤、UUID與異動時間的完整 Excel。匯出後請存放於受控加密磁碟或 NAS；操作人員、時間、格式、筆數及要求編號可於「系統管理 → 稽核紀錄」查閱。

學生名冊

支援網站 17 欄格式與桃園市學務系統匯出名冊；國小可使用 1–6 年級，國中可使用 7–9 年級，國小國中並存學校可使用 1–9 年級。

身高體重視力

可匯入桃園格式，亦可匯出 14 欄舊式 Excel，畫面明確標示「提供桃園學務系統匯入使用」。

待確認學生如何判斷同學期重新匯入時，系統會正規化學號、姓名與識別資料，再以班級、座號及學生身分交叉比對；只有新名冊確實缺少的既有學生才會列入待確認。
歷史學生資料舊學期、轉出或畢業學生資料可逐筆勾選成為歷史封存紀錄，不會加入目前在學名冊。

  1. 上傳最新版更新檔1.2.1 以上可直接使用最新版 .shisupdate，不必安裝中間版本。
  2. 核對版本與說明確認檔案已驗證、最低版本與檔案數量合理。
  3. 套用更新重新輸入管理員密碼；服務短暫重新啟動。
  4. 確認結果重新整理畫面，檢查目前版本與狀態是否完成。
清除測試資料並重新匯入此功能只適用於安裝測試完成、準備正式上線前。正式資料已開始使用後，不可將它當成一般刪除功能。只有具系統管理權限的管理員能看見及執行。
  1. 開啟管理員資料維護依序進入「系統管理 → 資料備份與還原」，捲動到頁面最下方的「管理員資料維護」。護理師及一般帳號不會顯示此區塊。
  2. 核對影響範圍確認學生、班級、傷病、健檢、匯入批次、報表、封存與檔案筆數。若數量與預期不符，立即停止。
  3. 啟動清除確認按「清除並重新初始化」，閱讀不可逆影響，再輸入指定文字「清除業務資料」。
  4. 完成本人驗證輸入目前登入管理員的本人密碼。系統會先建立完整 PostgreSQL 備份並驗證可讀性；任何一步失敗都不會清除資料。
  5. 保存完成憑證畫面會顯示備份檔名與位置。確認成功後再前往「資料匯入」，匯入正式學生名冊。
  6. 依序重新匯入先匯入學生名冊並完成班級座號檢核，再匯入重大傷病、身高體重視力及必要的歷年傷病資料。
舊版畫面也可清除1.2.64 起相容舊版頁面使用的清除指令。由舊版本直接升級後，即使瀏覽器仍暫時載入舊畫面，也會安全轉入新版清除流程；管理員密碼驗證、完整備份與交易式清除仍全部執行。

會清除

學生主檔、編班、健康與傷病資料、匯入批次、報表、畢業或轉出封存及相關檔案。

會保留

學校與學期設定、管理員與護理師帳號權限、系統代碼、備份排程、更新紀錄及獨立稽核紀錄。

國小畢業資料判斷國小學制只允許目前在學名冊使用 1–6 年級。已畢業學生及七年級以上的歷史班級會保留，不會阻擋學制設定；若仍有在學或留校狀態的超齡學生，請先完成畢業封存。
感染關聯設定的新位置由護理人員進入「傷病與追蹤 → 感染關聯設定」，維護相鄰教室、共用空間或固定共同活動的班級。此功能已不放在學校基本設定，既有關聯資料不需重新建立。
唯一管理員忘記密碼請到安裝主機的 Windows 開始功能表，開啟「SHIS Local 管理員密碼救援」。接受 UAC 管理員授權後，輸入管理員帳號、指定確認文字及兩次臨時新密碼。系統會暫停網站服務、建立並驗證完整資料庫備份、重設密碼、撤銷全部既有登入，再恢復服務；首次登入會強制修改正式密碼。

設備汰換與災難復原

主機完整備份與資料移轉

與每日自動備份不同主機移轉工具會封裝整套 PostgreSQL 資料庫及舊主機的資料解密金鑰，適合設備故障、汰換或開發環境更換。產生的 .shismove 不需要密碼，因此必須視為高度敏感檔案。

舊主機：網頁匯出

  1. 以系統管理員登入「備份與還原」。
  2. 在「主機完整移轉」按「建立移轉檔」，重新驗證本人密碼。
  3. 等待背景封裝完整 PostgreSQL 與來源資料金鑰。
  4. 下載 .shismove，核對大小與 SHA-256，存入受控加密磁碟。

新主機：網頁匯入

  1. 先完成 SHIS Local 安裝與初始化。
  2. 選取 .shismove；系統以 8 MB 分段上傳，中斷後可重選同一檔案續傳。
  3. 驗證通過後重新驗證密碼並輸入「移轉主機資料」。
  4. 系統先備份新主機，再整庫還原、接管金鑰、更新資料結構及健康檢查；失敗自動回復。
階段系統動作管理員確認
匯出前讀取完整資料庫與資料金鑰暫停新增或修改資料
匯入前在新主機建立 pre-host-import 備份確認新主機可正常開啟
匯入中驗證封裝、還原資料庫、取代金鑰、執行遷移不可關機或中斷磁碟
完成後重新啟動 API、Web 與 Gateway抽查學生、傷病、健檢及報表
  1. 安全保管移轉檔只能放在受控加密磁碟或 NAS，不可透過公開連結傳送。
  2. 失敗處理不要清除新主機資料；保留錯誤畫面及 C:\ProgramData\SHIS Local\logs 後再檢查。
  3. 完成清理確認新主機運作及備份正常後，安全刪除不需要的移轉副本。

版本更新紀錄

版本加入或修改的功能資料影響
1.3.5修正每日自動備份排程狀態回填；停用改為必須輸入指定確認文字，避免調整路徑或時間時誤停用。API 回傳資料庫實際保存的啟用狀態；不修改既有備份檔或業務資料。
1.3.4新增網頁版主機完整移轉，可串流下載、8 MB 分段上傳及中斷續傳，不受 128 MB 限制。匯入前重新驗證；SYSTEM 背景程序先備份、失敗回復、健康檢查並留下稽核紀錄。
1.3.3主機移轉 V2.2 支援免輸入密碼的完整資料庫及來源資料金鑰移轉，不受瀏覽器檔案大小限制。匯入前備份目的主機資料庫與設定；失敗自動回復，成功須通過 API、Web 與 Gateway 健康檢查。
1.3.2修正「系統管理 → 稽核紀錄」點擊後無法開啟；頁面網址重新載入後可正確顯示。稽核紀錄依正式 audit.read 權限開放，管理員及主管／稽核者均可查閱，仍不提供修改或刪除。
1.3.1教育局匯出補齊原傷病管理檔的六種報表：傷病日誌分月、分班、分日期，傷病人數分月，傷病統計分月及學年度統計；分組報表可一次建立所有月份、班級或日期工作表。沿用 1.3.0 的本人密碼重新驗證與不可修改稽核紀錄，並新增保存實際報表種類；不修改既有傷病資料。
1.3.0傷病報表新增「資料匯出」：可按學年度下載教育局既有欄位格式，或含身分證、學號、完整班級、生命徵象、處置、追蹤、UUID及異動時間的完整 Excel。系統管理新增可依日期、結果及關鍵字查詢的稽核紀錄。匯出前必須重新驗證本人密碼；匯出格式、筆數、操作人員、時間、結果與要求編號均留存於不可修改或刪除的稽核紀錄。不修改既有傷病資料。
1.2.85修正舊更新器將首頁結果存入 $home、與 Windows PowerShell 唯讀 $HOME 變數衝突而必然失敗的問題。受影響主機需執行 1.2.85 完整安裝程式做一次就地修復，之後可恢復一般更新。就地修復會保留既有 PostgreSQL 資料庫、設定與備份；不可先解除安裝舊版。
1.2.84舊更新器使用的 Gateway 健康端點固定回傳最小存活狀態，並新增探測來源與上游結果紀錄；新版仍以獨立就緒端點檢查 PostgreSQL。健康回應只含 ok，不透露版本或主機資訊；不修改業務資料。
1.2.83新增 1.2.70 舊更新器專用的本機 Gateway 相容健康回應，使新版更新器可順利接手；升級後仍完整驗證 API、PostgreSQL 與 Web。相容回應只接受主機本機連線，不改變區網 API 行為，也不修改業務資料。
1.2.82修正舊版更新器在 API 啟動維護期間誤判失敗；拆分程序存活與資料庫就緒檢查，新版更新器仍會完整驗證 Gateway、API、Web 與 PostgreSQL。不修改或刪除業務資料；更新失敗仍保留備份並自動回復。
1.2.81保留工作臺傳染病統計、同班警示、備註範本修改與 Google 排程管理；暫時移除 Word 下載，仍可列印或另存 PDF。舊更新器的首頁探測改依主機本機連線判斷，不再依賴 PowerShell User-Agent。
1.2.80新增舊版 PowerShell 更新器相容健康探測與新版分項健康檢查。部分環境的 PowerShell 未送出預期 User-Agent 而安全回復；請直接使用 1.2.81。
1.2.79Word 模組改為下載時才載入，首頁首次回應效能已改善。部分舊更新器仍以完整首頁 GET 判斷健康而安全回復；請直接使用 1.2.80。
1.2.78補齊 1.2.77 遺漏的 Word 正式執行相依套件。部分低資源主機仍因首頁預先載入 Word 模組而超過健康檢查時間；請直接使用 1.2.79。
1.2.77新增工作臺流感／腸病毒與同班警示、個人備註範本修改、Google 同步排程修改與刪除、三套可編輯 Word 通報單。此版本因 Word 元件缺少正式執行相依套件，部分主機更新時會自動回復舊版；請直接使用 1.2.78。
1.2.76修正安裝健康檢查與 PowerShell HOME 唯讀變數名稱衝突。首頁與 API 已正常時，安裝程式可正確完成，不再誤報失敗。
1.2.75補齊 Web 正式執行所需的 React 相依套件，修正完整安裝後首頁短暫出現再回到 503。發行內容不再依賴開發目錄；模組載入錯誤會完整寫入紀錄。
1.2.74修正重新開機後 Web 服務反覆退出及首頁 503；更新完成前會同時驗證 API 與首頁。若首頁無法啟動，更新不會誤判成功，並會自動回復上一版程式與服務檔。
1.2.73新安裝或尚未設定過排程的學校，會自動啟用每日 02:00 本機完整資料庫備份，並保留 30 天。服務啟動時建立缺少的設定；錯過當日時間會補做。曾停用或自訂的設定不會被覆寫。
1.2.72允許主機的本機管理員帳號直接讀取系統 logs 資料夾，不必以提升權限的檔案總管開啟。只授予讀取與列出權限；一般使用者不開放，系統服務寫入權限維持不變。
1.2.71修正 1.2.70 更新後部分主機停在「系統服務正在啟動」；累積更新包現在會同步更新 Node 執行環境。更新前會備份原 runtime，失敗時連同程式一起回復；不修改既有資料庫內容。

1.2.69更新 Fastify、fast-uri 與 nanoid 正式相依套件，修補輸入驗證、網址處理及資源耗盡弱點。正式相依套件稽核為 0 個已知弱點；不變更資料庫與備份格式。
1.2.68修正傳染病通報清單讀取與新增通報時使用錯誤的學生、學期及在學狀態欄位。不修改既有學生或傷病資料；恢復流感、腸病毒通報正常運作。

1.2.66啟用同源 Content Security Policy，限制外部程式、物件、框架及瀏覽器權限；縮減免登入健康與初始化端點資訊。降低跨站內容注入與系統指紋辨識風險，不影響校內正常操作。
1.2.65新增主機本機管理員密碼救援工具；限 Windows 系統管理員執行，救援後強制改密碼並撤銷既有登入。先建立完整可讀備份；不修改學生、健康及傷病資料。
1.2.64修正舊版本升級後清除資料無效；舊版清除網址與確認文字會安全導入新版完整流程。清除前強制備份並驗證；保留學校、學期、帳號、設定、更新與稽核紀錄。
1.2.63工作台「連續受傷警示」可直接開啟學生個人傷病紀錄，並自動套用目前學生篩選。不修改資料庫結構及既有傷病資料。
1.2.62感染關聯設定移至「傷病與追蹤」，護理師可維護相鄰教室、共用空間與共同活動班級。保留既有感染關聯資料，不需重建。
1.2.61完善國小學制判斷：國小目前在學名冊限 1–6 年級，已畢業或七年級以上歷史班級不阻擋設定。不變更歷史學生、健康及傷病資料。
1.2.60學校基本設定只保留學校資料；清除業務資料與感染關聯設定改為獨立功能。既有設定及關聯完整保留。
1.2.59「清除業務資料並重新匯入」移至「系統管理 → 資料備份與還原」，僅管理員可操作。執行前要求本人密碼、完整 PostgreSQL 備份及可讀性驗證。
累積更新1.2.1 以上版本可直接套用最新的正式 .shisupdate，不必逐版安裝；套用前仍會驗證簽章、檔案雜湊並建立資料庫備份。

排除問題

常見問題

其他電腦無法連線

確認主機服務已啟動、網址使用主機固定 IP 與 3000 連接埠，並檢查 Windows 防火牆允許校內子網路連入。

畫面顯示沒有權限

確認目前登入帳號角色；護理師不應看到帳號管理、系統設定、備份還原或系統更新等管理功能。

唯一管理員忘記密碼

不能從其他電腦或登入頁直接重設。請在安裝主機使用 Windows 開始功能表的「SHIS Local 管理員密碼救援」，完成本機管理員驗證、備份與臨時密碼設定。若找不到工具，先使用最新版完整安裝程式修復。

匯入資料全部顯示錯誤

先確認匯入學期、檔案格式與學生名冊是否一致。錯誤列不會寫入，可修正共同原因後重新檢核。

更新長時間停在已排程

服務更新時可能短暫無法連線。等待數分鐘後重新整理；若仍未完成，由管理員查看更新紀錄與安裝記錄。

日期、姓名或中文字顯示異常

確認使用支援 UTF-8 的新版瀏覽器。Excel 匯入請避免以文字編輯器改存造成編碼或日期型態變化。
